# CI/CD Signal Inventory

> Status: maintained
> Applies to: ClassroomPath CI/CD workflow signal classification
> Last verified: 2026-05-01
> Source of truth: `docs/ci-cd-signal-inventory.md`
> Owner: ClassroomPath release automation

This inventory classifies scheduled and operator-triggered workflow signals so CI cost reductions do not weaken release evidence.

| Workflow                                  | Schedule                                | Signal class                                     | Environment                                             | Owner              | Required evidence                                                                               | Duplicate same-SHA policy                                                                                                                                             |
| ----------------------------------------- | --------------------------------------- | ------------------------------------------------ | ------------------------------------------------------- | ------------------ | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy.yml`                              | none                                    | blocking release gate                            | staging and production                                  | release operator   | deployment logs, staging verification env, release evidence bundle                              | Never suppress. Tag production deploys are non-cancelable.                                                                                                            |
| `release-candidate-images.yml`            | none                                    | blocking release gate                            | release candidate registry                              | release automation | digest-pinned RC image artifacts                                                                | Push runs may cancel obsolete refs; manual runs remain explicit evidence.                                                                                             |
| `production-client-update-canary.yml`     | `*/15 * * * *` plus post-deploy trigger | post-release health                              | production                                              | release automation | download canary artifact on schedule; platform canary artifacts after deploy or manual dispatch | Scheduled runs may skip when the same workflow already passed on the same SHA within 60 minutes. Post-deploy `workflow_run` and manual dispatch are never suppressed. |

Manual or reusable caller evidence is intentional.                                                                                                    |
| `linux-production-bootstrap-canary.yml`   | none                                    | blocking/advisory diagnostic depending on caller | production                                              | release automation | Linux bootstrap failure-boundary artifact                                                       | Never suppress. Presentation policy:

- Blocking gates fail loudly and publish release evidence.
- Advisory workflows must state `advisory` in their summary or issue context and avoid production-promotion wording.
- Maintenance workflows must name the owner, next action, and whether production release evidence is affected.
- Required failure artifacts stay under `always()` when diagnosis depends on them.
